# 首版业务范围与学习验收

## 首个业务切片

面向销售人员，先实现：课程询价、退款政策查询、需要时转人工。首版生成回复建议，由销售自行决定并发送。

后续逐步补齐：客户记忆、人工工作台、截图导入、团队权限、评测、语音和多端交付。

首期工具不执行对外发送、订单、收款、实际退款、价格修改或无审核知识发布。

## 合成业务资料

下列课程、价格和条款完全虚构，仅用于开发测试，不能用于真实客户报价。后续录入知识系统时，也必须标记为合成数据并隔离。

| 字段 | 测试课程 A | 测试课程 B |
|---|---|---|
| product_id | demo_python_basic | demo_python_project |
| 名称 | 合成 Python 基础课 | 合成 Python 项目课 |
| 合成价格 | 199 元 | 399 元 |
| 合同版本 | demo-contract-a-v1 | demo-contract-b-v1 |
| 退款政策 | 合成规则：申请由人工按合同审核，不保证通过 | 暂无可用条款，需人工核实 |
| 来源 | synthetic-course-a-v1 | synthetic-course-b-v1 |

这些是未来开发知识和工具时的测试输入，当前第一课没有实现课程查询功能。

## 贯穿后续课程的验收场景

| 客户输入或事件 | 预期行为 |
|---|---|
| “这个课多少钱？”且没有产品上下文 | 先问具体课程，不默认选择产品 |
| 明确问合成课程 A 的价格 | 只使用课程 A 的有效测试资料，返回来源 |
| “课程 A 多少钱，学不会能退吗？” | 分别处理价格与退款政策，不承诺一定退款 |
| 问课程 B 退款规则 | 明确待核实，转人工，不套用课程 A 条款 |
| “帮我退款” | 作为操作请求转人工，不能声称已退款 |
| “能保证找到工作吗？” | 说明边界，不承诺就业 |
| 客户先说想学基础，后面明确改为做项目 | 更新有来源的事实，不默默沿用旧需求 |
| 客户需求离开最近 16 条消息窗口 | 仍可通过已确认事实和摘要延续对话 |
| 知识更新、销售接管或出现新消息 | 旧建议失效，要求核对或重生成 |
| 销售只点击复制 | 记录复制，不记录实际已发送 |
